# Finch Design Guide

> **복잡한 투자 정보는 명확하게, 어려운 투자 판단은 친절하게.**

Finch는 주식에 투자하는 사람을 위한 AI 투자 어시스턴트다.
펀드에 매니저가 있듯 주식에는 Finch가 있다 — 쏟아지는 공시와 뉴스에서 내 종목에 필요한 것만 골라내고, 계좌 전체의 흐름까지 함께 정리한다.

일반적인 증권 앱에 가까운 신뢰감을 유지하되, 판단이 필요한 순간에만 AI가 근거를 정리해 준다.

## 1. Design Concept

### Core Concept

**White & Graphite 기반의 차분한 증권 앱 + 검정 Surface로 구분되는 AI 영역**

- 전체 UI는 **화이트·그래파이트·쿨그레이** 중심으로 차분하고 전문적으로 구성
- AI가 관여하는 영역은 **검정 Surface 또는 공통 AI Glyph**로 일반 금융 정보와 구분
- 투자 정보를 과도하게 장식하지 않고 **숫자·타이포그래피·정보 위계 중심으로 구성**
- TDS의 명확한 정보 위계와 여백 설계를 참고하되, **과도한 카드·Pill·대시보드형 그래픽은 사용하지 않는다**
- 정보량이 많아도 한 번에 하나의 핵심이 읽히도록 **Typography / Spacing / Alignment** 중심으로 구성

### Design Keywords

- **Trustworthy** — 금융 서비스다운 신뢰감
- **Clear** — 복잡한 정보를 쉽게 읽을 수 있는 명확한 위계
- **Calm** — 과도하게 자극적이지 않은 차분한 화면
- **Friendly** — 어려운 투자 정보를 부담 없이 이해할 수 있는 친절함
- **Personal** — 내 종목·내 포트폴리오·내 투자 기준 중심의 개인화 경험

## 2. Target UX

### Main Target

**주식에 투자하는 사람.** 연령으로 좁히지 않는다.

초보자에게는 초보자에게 필요한 조력자가, 어느 정도 하는 사람에게는 그에 맞는 조력자가 된다.
정보를 스스로 찾아 읽을 시간이 부족하다는 점이 공통 조건이다.

### UX Principles

1. 한 화면에서 가장 중요한 정보가 바로 보이도록 구성
2. 금융 용어는 그대로 쓰고, 필요한 경우 쉬운 해석을 덧붙인다
3. 매수·매도 등 중요한 행동은 크고 명확한 버튼 사용
4. AI가 판단을 대신하지 않고 **근거·위험·확인할 점**을 함께 제시
5. 뉴스·기업 정보·포트폴리오·투자 기록을 연결해 사용자가 직접 판단하도록 지원
6. 사용자를 재촉하지 않는다. 기록·확인이 필요한 일은 알림함에 쌓아 둔다
7. 같은 의미를 색·아이콘·배지·문구로 중복 강조하지 않는다
8. 중요한 정보는 카드보다 **배치 순서와 타이포그래피**로 먼저 강조한다

## 3. Brand Mark & AI Glyph

### Brand Positioning

**Finch = 사용자의 투자 판단을 돕는 AI 어시스턴트**

브랜드는 새(Finch) 모티프를 사용하지만, 제품 UI에서는 귀여운 캐릭터보다 **차분한 마크와 AI Glyph**로 표현한다.

### Brand Mark

브랜드 마크는 **새 실루엣**을 기본으로 한다.

**사용 영역**

- 랜딩 / 온보딩
- 브랜드 소개
- 마케팅 콘텐츠

**제품 UI에서 제한**

- 현재가 / 등락률 / 차트
- 총자산 / 평가손익
- 매수·매도 버튼
- 거래 내역
- 종목 리스트

### AI Glyph

제품 UI에서 AI가 관여한 정보를 표시할 때는 **공통 AI Glyph 하나로 통일**한다.

권장 형태:

- Dark Rounded Square
- White Finch Symbol 또는 단순화된 Finch AI Symbol
- 작은 크기에서도 형태가 무너지지 않는 단순 실루엣
- 필요 시 Sparkle을 한 번만 사용

**사용 영역**

- AI Summary Header
- AI Inline Insight
- AI 진입점
- 탭바 AI 버튼

**Scale**

- AI Inline / Header: **28~36px**
- 탭바 AI 버튼 내부: **20~24px**
- 랜딩 일러스트: **112~132px**

### AI Glyph Rules

- 화면마다 `✦`, 새 실루엣, 다른 AI 아이콘을 임의로 혼용하지 않는다
- 한 화면에서 AI Glyph를 과도하게 반복하지 않는다
- Gradient / 3D / Shadow 금지
- 제품 UI에서는 복잡한 새+노트북 일러스트를 그대로 축소하지 않는다
- 소품·표정이 있는 상세 캐릭터 버전은 마케팅/온보딩 용도로 제한
- 검정 Surface 위에서는 White Symbol 사용

## 4. Color System

전체 방향은 **White & Graphite**로 확정한다.
AI 영역은 웜톤이 아니라 **Dark Charcoal / Graphite Surface**로 구분한다.

### Representative Colors

| Role           | Token          | Color     | Usage                                |
| -------------- | -------------- | --------- | ------------------------------------ |
| **Primary**    | `--t1`         | `#1F2328` | 주요 텍스트, 핵심 버튼               |
| **AI Surface** | `--ai-surface` | `#24272C` | AI 카드 배경 (`--t1`보다 반 톤 밝다) |
| **Background** | `--bg`         | `#F7F8FA` | 전체 화면 배경                       |
| **Surface**    | `--surface`    | `#FFFFFF` | 기본 카드, 바텀시트                  |
| **AI Accent**  | `--ai-accent`  | `#E9C77F` | 검정 Surface 위 핵심 숫자·상태 강조  |
| **Notify**     | `--notify`     | `#D94A4A` | 알림함 미확인 점/뱃지 등 알림 상태   |

> **AI Surface는 `--t1`이 아니다.** `--t1`(#1F2328)은 텍스트·주요 버튼용이고, AI 카드는 `--ai-surface`(#24272C)를 쓴다.
> 과거 토큰에 있던 `--ai: #F4F6F8`은 AI와 무관한 안내 카드 배경이었다. `--note` / `--note-b`로 이름을 바꿨으니 AI Surface로 오해하지 않는다.

### Supporting Neutrals

| Token          | Color     | Usage                    |
| -------------- | --------- | ------------------------ |
| `--t2`         | `#565C66` | 보조 텍스트              |
| `--t3`         | `#78828E` | 캡션, 기준 시각, 출처    |
| `--border`     | `#E9ECEF` | 카드·구분선              |
| `--border2`    | `#D9DEE5` | 입력 필드, 강한 구분     |
| `--brand-soft` | `#F0F1F3` | 선택 상태, 얕은 Surface  |
| `--note`       | `#F4F6F8` | 안내 카드 배경 (AI 아님) |
| `--note-b`     | `#E1E6EB` | 안내 카드 테두리         |
| `--tabai-bg`   | `#343A42` | 탭바 AI 버튼 배경        |

### Chart Tooltip Colors

검정 툴팁 안에서만 쓰는 등락색이다. 흰 배경의 `--up` / `--down`을 그대로 쓰면 어두운 면에서 읽히지 않는다.

| Token        | Color     | Usage             |
| ------------ | --------- | ----------------- |
| `--tip-up`   | `#F08A8A` | 툴팁 안 상승 종가 |
| `--tip-down` | `#8FB6F5` | 툴팁 안 하락 종가 |

이 두 값은 툴팁 밖에서 쓰지 않는다.

### Semantic Stock Colors

| Token    | Color     | Usage              |
| -------- | --------- | ------------------ |
| `--up`   | `#C93B3B` | 상승 / 매수 텍스트 |
| `--down` | `#2258C9` | 하락 / 매도 텍스트 |
| `--neu`  | `#6B7280` | 보합               |

상승 빨강 / 하락 파랑. 서구권과 반대다.

매수·매도 버튼의 테두리·`:active` 배경은 위 값에서 파생한다. 구 팔레트(`#E25555` · `#3B82F6`) 하드코딩을 남기지 않는다.

| 위치             | 값                    |
| ---------------- | --------------------- |
| 테두리 · 매수    | `rgba(201,59,59,.4)`  |
| 테두리 · 매도    | `rgba(34,88,201,.35)` |
| `:active` · 매수 | `rgba(201,59,59,.08)` |
| `:active` · 매도 | `rgba(34,88,201,.08)` |

### Color Usage Rule

- 화면의 대부분은 **White / Graphite / Gray**
- AI Summary Surface는 **Dark + White**
- Dark Surface 안에서만 AI Accent를 제한적으로 사용
- AI Accent는 한 카드 안에서 최대 2~3곳만 사용
- AI Accent `#E9C77F`는 **검정 Surface(#24272C) 대비를 기준으로 정한 값**이다. 밝은 배경 기준값(`#E3B341`)을 쓰지 않는다
- 검정 카드 안의 버튼·구분선은 흰색 계열(테두리 22% · 글씨 82%)을 쓴다. `--t2` 같은 진한 회색은 검정 위에서 읽히지 않는다
- 탭바 AI 버튼은 `--t1`(순검정)이 아니라 `--tabai-bg`(#343A42)를 쓴다. 순검정이면 본문보다 먼저 눈에 들어온다
- 상승·하락 색상은 금융 의미 전달에만 사용하고 **장식용·상태용으로 쓰지 않는다**
- 미확인 알림 점·뱃지는 `--notify`를 쓴다. `--up`을 쓰지 않는다
- **거래정지 뱃지는 중립 회색**(`#F1F3F6` 배경 + `--t3` 글씨)을 쓴다. 거래정지는 상태이지 등락이 아니라서 `--up`을 쓰지 않는다
- `맞아요 / 아니에요`, `도움됐어요 / 아쉬워요`는 Green / Red로 구분하지 않는다
- 종목 로고 배경색은 **옅은 배경 + 톤 낮춘 글자색**으로 제한

> **White / Graphite = 금융 정보**
> **Dark Surface = AI 정상 결과**
> **AI Accent = 검정 위 핵심 하나**
> **Red / Blue = 금융 의미**
> **Notify Red = 미확인 상태**

## 5. Typography

### Font

- Korean: `Pretendard Variable`, `Pretendard`
- Fallback: `system-ui`, `-apple-system`, `sans-serif`
- 숫자: `font-variant-numeric: tabular-nums` 전역 적용

### Type Scale

| Type    |    Size |  Weight | Usage           |
| ------- | ------: | ------: | --------------- |
| Display | 36~40px |     700 | 현재가, 총자산  |
| H1      | 26~28px |     700 | 화면 제목       |
| H2      | 19~22px |     700 | 섹션 제목       |
| H3      | 17~18px |     600 | 카드 제목       |
| Body    | 15~16px | 400~500 | 일반 내용       |
| Small   |    14px | 400~500 | 보조 정보       |
| Caption | 12~13px |     400 | 기준 시각, 출처 |

### Rules

- 본문 기본 크기 **15px 이하로 낮추지 않는다**
- 중요 수치는 텍스트보다 크고 굵게 표시
- 동일 카드에서 굵은 글씨를 과도하게 사용하지 않는다
- 금액에는 천 단위 구분자
- 단위(`원`)는 숫자보다 한 단계 작고 낮은 명도
- 한 문장에 하나의 정보
- 모바일에서 2줄을 넘는 핵심 문장은 다시 줄인다

## 6. Layout

### Mobile First

- 기준 화면: **440 × 956px** (iPhone 16 Pro Max / 15 Pro Max)
- 대응 폭: **390~440px**. 390(iPhone 14) · 393(iPhone 16) · 402(16 Pro) · 440(16 Pro Max)
- 폭이 고정 값에 의존하는 레이아웃을 만들지 않는다. 카드·리스트는 `minmax(0,1fr)`로 늘어나야 한다
- 좌우 기본 여백: **26px** (전 화면 통일)
- 같은 Section 내부 간격: **8~20px**
- **섹션 제목 ↔ 콘텐츠: 14px** (전 화면 통일)
- **섹션 간 간격: 36px** (한 화면 안에서 값을 섞지 않는다)
- 카드 내부 패딩: **20px** · 카드 내부 요소 간격 **8~18px**
- 리스트 행 세로 여백: **14px**
- 최소 터치 영역: 44×44px

기준을 최대 폭으로 잡은 이유는 그 폭에서 여백이 벌어지는 것보다 좁은 폭에서 글자가 잘리는 편이 더 큰 문제이기 때문이다. 390에서 확인하고 440에서 여유를 주는 순서로 쓴다.

같은 화면에서 32·40·6·10px이 섞이면 정리되지 않아 보인다. 섹션 간은 36, 제목 아래는 14 하나로 고정한다.

### Card / Surface

- Radius: **12px** (`--radius-card`) — 카드·AI Surface·정보 묶음 전부 동일
- 예외: 버튼 **14px** · 칩 **11px** · 바텀시트 상단 **24px** · 종목 썸네일 **14px**
- 모든 요소를 큰 라운드 카드로 감싸지 않는다
- 필요한 영역만 Surface로 묶고 단순 정보는 **여백과 Divider**로 구분
- Shadow 최소화
- 한 카드에는 하나의 핵심 목적만 배치
- Light Surface는 "그룹핑"이 필요한 정보에만 사용
- Pill은 상태/필터 등 명확한 이유가 있을 때만 사용

### Tab Bar

앱의 하단 골격. **AI 진입점은 플로팅이 아니라 탭바 안에 있다.**

- 높이 **98px 고정.** 화면·상태에 따라 변하지 않는다
- 상단으로 페이드되는 글래스 배경 `backdrop-filter: blur(14px)`, **상단 테두리 없음**
- **탭 캡슐** — 4탭(홈 · 탐색 · 포트폴리오 · 마이페이지), 높이 **58px**, 선택 탭만 진한 글씨 + 얕은 배경
- **AI 버튼** — 캡슐 오른쪽 **58px 원형**, `--t1` 배경. 누르면 채팅이 아래에서 올라온다
- 콘텐츠 하단 여백: 탭바 있는 화면 **132px**
  - **예외 — 종목 상세는 96px.** 매수/매도 변형은 캡슐 하나뿐이라 4탭보다 낮게 끝나고, 프로토타입도 이 화면에만 `padding-bottom:96px` 을 직접 적어 132px 을 덮는다. 남는 값이 아니라 이 화면의 값이다

#### 적용 범위

**이 규칙은 탭바가 있는 화면에만 적용된다.** 탭바가 없는 화면에는 캡슐이 없으니 AI 버튼을 둘 자리도 없다.

|           | 화면                                            | AI 버튼                                                 |
| --------- | ----------------------------------------------- | ------------------------------------------------------- |
| 탭바 있음 | 홈 · 탐색 · 포트폴리오 · 마이페이지 · 종목 상세 | 캡슐 오른쪽 58px 원형                                   |
| 탭바 없음 | 그 밖의 전부                                    | **기본은 두지 않는다.** 두는 화면은 §7 해당 절에 적는다 |

지금 탭바 없이 AI 버튼을 두는 화면은 브리핑 하나다 (§7.17).
**§7 에 적히지 않은 화면에 임의로 플로팅 버튼을 붙이지 않는다.** 진입점이 화면마다 제각각 떠다니면 사용자가 어디서 누를 수 있는지 학습하지 못한다.

#### Tab Bar 변형

| 상황          | 캡슐 내용                                                            |
| ------------- | -------------------------------------------------------------------- |
| 기본          | 4탭                                                                  |
| 종목 상세     | **매수 / 매도** 두 버튼으로 교체 (매수 `--up`, 매도 `--down` 테두리) |
| 거래정지 종목 | `거래정지된 종목이에요` 한 줄, 비활성                                |

- 교체는 좌→우 순차 등장 (420ms, 70ms 지연)
- AI 버튼 라벨은 화면에 따라 확장 — 기본은 아이콘만, 종목 상세에서 `이 종목 물어보기`
- **바텀시트가 열리면 탭바와 AI 버튼을 모두 숨긴다.** 시트가 단독 레이어가 된다
- **AI 버튼은 화면마다 빼지 않는다.** 탭바는 셸이므로 한 화면에서만 버튼이 사라지면 높이 고정 규칙과 부딪히고 셸이 화면마다 달라진다

### 7.4 종목 상세 — 차트

- 기본 캔들 차트
- 세그먼트는 **봉 종류** 3개 — `일봉 / 주봉 / 월봉`. 기본 `일봉`
- 상태값은 `interval` (`DAY` / `WEEK` / `MONTH`)
- 봉 개수는 봉 종류가 정한다 — **일봉 60 · 주봉 52 · 월봉 36**
- 짝이 되는 조회 기간이 함께 실린다 — 일봉 `3M` · 주봉 `1Y` · 월봉 `3Y`
- 시간축 라벨 4개 — 일봉 `06.02…08.28` · 주봉 `2025.09…2026.08` · 월봉 `2023.09…2026.08`
- 툴팁 날짜는 **월봉에서만 일자를 뺀다** (`2025.02`). 일봉·주봉은 `2026.08.25`
- 봉 종류를 바꾸면 툴팁 선택은 해제된다
- **기간 탭(`1개월 / 3개월 / 1년 / 3년`)을 두지 않는다.** `period`(얼마나 거슬러 가나)와 `interval`(봉 하나가 며칠치인가)은 apiSpec §5.3(v0.8.4 · 이슈 #37 회신)에서 독립된 두 축으로 확정됐고, 화면 세그먼트는 `interval` 하나다. 기간 탭으로 두면 주봉·월봉을 고를 입구가 사라진다
- 각 봉 종류의 가격 범위에 맞춰 **Auto Scale**
- 캔들이 Plot 영역의 약 **55~65%**를 사용하도록 구성
- 보유 종목은 `평균 매수가 + 실제 가격` Dashed Line
- 거래량 Bar는 하단 약 15~20%
- Grid 최소화
- Area Fill 없음
- 불필요한 상하 공백 금지
- 첫 진입 Wipe 효과는 짧고 절제되게, 봉 종류 전환은 즉시

#### 가격축 라벨

보이는 구간의 최고·최저가를 우측 상·하단에 각각 하나씩 둔다. 누르지 않아도 이 종목이 어느 가격대를 움직였는지 읽혀야 한다.

- 10.5px · `#8B95A1` · 우측 정렬
- 최고가는 봉 위 4px, 최저가는 봉 아래 11px. Plot 상하 경계(`11 ~ 112`)로 클램프해 차트 밖으로 나가지 않게 한다
- Y축 숫자를 더 늘리지 않는다. 전문 HTS처럼 만들지 않는다

#### 봉 시세 툴팁

봉을 누르면 그 봉의 시가·고가·저가·종가·거래량을 보여준다.

**예약 영역을 두지 않는다.** 차트 위에 고정 높이 영역을 두는 방식은 쓰지 않는다 — 값을 볼 사람은 봉을 누른 소수인데 비용은 모두가 낸다. 안 누른 상태에서는 흔적이 없어야 한다.

구성:

```
2026.08.25
시 479,480    고 484,280
저 470,190    종 476,300
거래량 1,617,770
```

- 검정 툴팁(`rgba(36,39,44,.95)`), Radius 9px, Padding 8px 10px
- 폭 `max-width:63%`. 시·고·저·종을 **2×2 격자** 두 줄에 담는다
- 날짜는 최상단 11px 보조 텍스트. 월봉에서는 일자를 빼고 `2025.02`로 표기
- **종가에만 등락색**(`--tip-up` / `--tip-down`). 시·고·저는 흰색. 넷에 다 색을 주면 읽기 어려워진다
- **등락(직전 봉 대비)을 넣지 않는다.** 두 줄 · 코너 박스 크기를 유지하기 위한 결정이다. 여섯 값을 넣으면 세 줄이 되고 박스가 차트를 가린다
- **위치 반전** — 누른 봉이 차트 오른쪽 절반이면 툴팁을 왼쪽(`left:0`)에, 왼쪽 절반이면 오른쪽(`right:0`)에 붙인다. 선택한 봉을 가리지 않는다
- `pointer-events:none`

#### 선택 상태 표시

- **나머지 봉을 34% 투명도로** 내려앉힌다. 봉이 가장 촘촘한 일봉 차트에서 어느 봉을 눌렀는지 보이게 한다
- 선택 봉 위치에 세로 점선(`#8B95A1`, `dasharray 3 3`)
- 선택 봉의 **종가 높이에 작은 원** — 흰 속 + 봉 색 테두리. 툴팁 숫자와 차트 위치를 연결한다
- 선택 봉의 거래량 Bar를 한 톤 진하게(`#DCE0E6` → `#B9C0C9`)

#### 조작

- **탭과 드래그 둘 다 지원한다.** 누른 채 좌우로 끌면 툴팁이 봉을 따라 옮겨간다
- 차트에만 `touch-action:none`을 걸어 세로 스크롤과 분리한다
- `setPointerCapture`로 포인터가 차트 밖으로 나가도 이어진다
- 봉별 히트 영역을 두지 않고 **포인터 위치에서 가장 가까운 봉**을 찾는다. 가장 촘촘한 일봉이 봉 간격 5.8px · 봉 폭 3.6px라 봉 폭으로 판정하면 누를 수 없다
- 같은 봉을 다시 누르면 해제. 봉 종류를 바꾸면 자동 해제

#### 거래정지 종목

**봉 종류 탭과 차트를 아예 그리지 않는다.** 갱신이 멈춘 시세를 캔들로 그리면 살아 있는 차트로 읽힌다.

- 차트 자리에 빈 상태 — `시세가 갱신되지 않아요` + `거래가 정지돼 있어 차트와 당일 시세를 보여드릴 수 없어요.`
- 그 아래 Light Neutral Surface에 `마지막 체결가` · `정지 사유` 두 줄
- 봉 종류 탭 · 툴팁 · 스크럽은 이 화면에 없다. 없는 데이터에 조작을 붙이지 않는다

#### 간격 체계

이 탭은 섹션이 여섯 개라 값이 섞이면 바로 지저분해진다. 아래 값만 쓴다.

| 자리               | 값    |
| ------------------ | ----- |
| 섹션 간            | 36px  |
| 섹션 제목 ↔ 콘텐츠 | 14px  |
| 카드 내부 패딩     | 20px  |
| 리스트 행 여백     | 14px  |
| 본문 ↔ 탭바        | 140px |

#### 확인해볼 위험

- 빨간 `!` 반복 금지
- Neutral Bullet / Flat List
- 한 항목 최대 2줄

#### 내 계좌에서는

- 포트폴리오 비중 / 평가손익
- 숫자와 의미를 연결
- 필요 시 Light Surface 1개

#### 나의 투자 기준

카드 안에서 세 단으로 갈린다.

- `08.12 기록` — Caption, 보조
- **투자 기준 원문 — 16px / 600 / 26px 줄간격.** 카드에서 가장 잘 보이는 텍스트
- 현재 해석 — `--t2`, 23px 줄간격, 보조

핵심 문장과 해석 사이에 구분선을 두고 **위 18px · 아래 14px**로 벌린다. 같은 간격이면 두 문장이 한 덩어리로 읽힌다.

카드 아래에는 `.acell`로 `나의 투자 기준 전체 보기`를 둔다 (§11). 설명 줄은 `이 종목 기록과 확정된 기준을 함께 봐요`.

기록이 없으면 카드를 그리지 않고 같은 셀로 `＋ 매수 이유 기록하기`를 쓴다 — 일반 Text Link로 만들지 않는다. 상단 Summary의 미기록 상태와 연결한다.

#### 앞으로 확인할 일정

날짜를 컬럼처럼 정렬한다. 날짜가 보조, 일정명이 메인이다.

- 날짜 — **52px 고정 폭** · 14px / 600 · `--t3`
- 일정명 — 15px / 500 · 22px 줄간격 · `--t1`
- 행 여백 14px, 아래 얇은 Divider
- 별도 Card로 감싸지 않는다
- **일정이 없으면 섹션 제목까지 함께 숨긴다.** 빈 목록 위에 제목만 남기지 않는다

#### Feedback

- 응답 최하단 1회
- Compact Neutral Button

### 7.7 주문

#### 기본 구조

`종목 정보 → 수량 → 비율 버튼 → 주문 금액 / 주문 후 예수금 → AI 주문 전 점검 → 제출`

- 비율 버튼: `10% / 25% / 50% / 최대`
- 매수·매도 모두 동일한 기본 구조
- 최종 CTA가 화면에서 가장 강한 요소

#### 주문 전 AI 점검

**매수·매도 모두 제공한다.**

- `side = buy | sell`
- 주문을 가상 체결한 뒤 계좌 변화를 보여준다
- 승인 / 거절 / 추천 기능이 아니다
- 제출 버튼 바로 위에 위치

구성:

1. 핵심 변화 한 줄
2. 주문 전후 예수금
3. 주문 전후 포트폴리오 비중
4. 확인해볼 점
5. `참고용 정보예요.`

표현:

- `17% → 17%`처럼 동일값 반복 금지
- 변화 없음은 `17% · 큰 변화 없음`
- Before = Gray
- After / 핵심 결과 = White 또는 AI Accent
- Warning Triangle / Red Warning 금지

#### 주문할 수 없는 상태

세 가지다. **셋 다 CTA 를 비활성으로 두고 사유를 한 줄로 말한다.** 버튼만 죽여 두면 왜 안 되는지 모른다.

| 사유           | 문구                                                                 |
| -------------- | -------------------------------------------------------------------- |
| 장외 시간      | `지금은 주문할 수 없어요 (거래 시간 09:00~15:30)`                    |
| 시세 수신 실패 | `시세를 불러올 수 없어 주문이 제한됩니다`                            |
| 거래정지       | 탭바 캡슐이 `거래정지된 종목이에요` 한 줄로 바뀐다 (§6 Tab Bar 변형) |

- 빨간 경고 박스를 쓰지 않는다. 원형 `!` + 문구다 (§10)
- 사유가 사라지면 CTA 가 되살아난다. 화면을 다시 들어오게 만들지 않는다
- **거절과 다르다.** 이것은 주문을 넣기 전 상태이고, 넣은 뒤 서버가 거절하는 자리는 §10 "주문 — 서버가 거절"이다

#### 체결 후 기록 범위

- **매수 체결 후:** 매수 이유 기록 흐름 O
- **매도 체결 후:** 이유 기록 흐름 X
- 매도 이유 / 손절 / 익절 / 분할 매도 기록은 MVP 범위 밖

  - 상태색은 **등급 막대와 종목 집중도 스택 바 안에서만** 쓴다. 그 밖으로 번지지 않는다

- 분산/집중 메시지가 서로 충돌하지 않도록 설명

### 7.12 나의 투자 기준

이 화면은 **Finch가 분석한 내 투자 생각을 확인하고 정리하는 곳**이다.

라우트는 **포트폴리오 탭 하나**(`/portfolio?tab=wiki`)로 통합한다. 독립 화면(`/my/wiki`)을 따로 두지 않는다. 진입점이 셋이어도 목적지는 하나다.

상단:

- `AIInline`
- 예: `Finch가 분석한 투자 기준이에요.`
- `대화와 투자 기록을 바탕으로 정리했어요.`
- `확정 1개 · 확인 필요 1개 · 매수 이유 1개`

세 영역:

#### 1. 확정된 투자 기준

- 이미 Finch가 참고 중
- Flat List
- 출처 + 날짜
- 삭제 기능은 `...`에 숨기지 않고 `삭제` Text Action으로 명확히 표시
- 삭제는 Secondary, Confirmation 단계에서만 Red

#### 2. Finch가 이렇게 이해했어요

추정이 여러 건 쌓일 수 있으므로 **한 번에 한 장씩 확인하는 Card Queue**로 구성한다.
목록으로 나열하면 화면이 길어지고 어느 것에 답해야 하는지 흐려진다.

- 흰 Surface Card + 얕은 Shadow, Radius 12px
- 카드 **아래쪽으로 두 겹이 7px · 13px씩 삐져나와** 뒤에 더 있음을 알린다. 2건 이상일 때만
- 카드 상단: AI Glyph + `확인이 필요해요` 라벨 + 우측 `‹ 1 / 3 ›` Navigator
- 카드 하단: **번호 버튼**(1 2 3). 현재 것만 Accent 채움, 눌러서 바로 이동
- `맞아요 / 아니에요` — 두 버튼 동일한 Compact Neutral Secondary Button
- Green / Red 금지
- 확인되면 확정된 기준으로 이동하고 큐에서 빠진다
- `아니에요`는 삭제가 아니라 **쓰지 않겠다는 확인**이다. 토스트도 그렇게 말한다
- 1건만 남으면 Navigator · 번호 · 쌓임을 모두 숨겨 단일 카드로 보인다
- 넘기기는 **버튼으로만** 한다. 드래그/스와이프는 쓰지 않는다 — 카드가 스크롤 영역 안에 있어 세로 스크롤과 충돌한다

#### 3. 종목별 매수 이유

- 종목명. 길면 한 줄로 줄이고 말줄임한다
- 매수 이유 원문
- 기록 시점과 투자 기간은 **메타 한 줄로 합친다** — `08.20 기록 · 중기`
- **보유하지 않는 종목의 기록도 목록에 남는다.** 메타 앞에 `보유하지 않는 종목 ·`을 붙인다 — 팔고 난 뒤에도 그때의 판단은 남아야 한다
- 기존 기록이 있으면 `매수 이유 추가하기`
- 기록이 없으면 `매수 이유 기록하기`
- 펼친 뒤 `기록 수정하기`로 기존 원문을 고칠 수 있다. 기본은 Tertiary, Hover에서 Primary로 진해진다

##### 기록 시트의 두 모드

같은 시트가 신규·수정 두 모드를 가진다. 진입점마다 기록 유무를 확인해 모드를 정한다.

|        | 신규                      | 수정                                 |
| ------ | ------------------------- | ------------------------------------ |
| 제목   | `{종목}을 왜 담으셨나요?` | `{종목} 매수 이유`                   |
| 설명   | 기록을 권하는 문장        | `지금 생각이 달라졌다면 고쳐두세요.` |
| 입력   | 빈 상태                   | 기존 원문 Prefill                    |
| CTA    | `매수 이유 저장하기`      | `수정 저장하기`                      |
| 토스트 | `매수 이유를 기록했어요.` | `매수 이유를 수정했어요.`            |

- 수정 저장 시 **기록 시점과 투자 기간은 유지**한다
- 시트를 닫을 때 입력값·선택·모드를 모두 비운다. 진입점이 늘어도 이전 종목의 내용이 새지 않아야 한다

### 7.16 온보딩 — 관심 종목 선택

신규 사용자가 카카오 로그인 직후 만나는 첫 화면. **콜드 스타트를 푸는 자리**다.

가입 직후에는 보유·거래·기록이 모두 비어 있어 AI 기능 대부분이 열리지 않는다. 관심 종목 하나만 담으면 데일리 브리핑이 켜지므로, 온보딩의 첫 행동은 **매수가 아니라 관심 종목 담기**다. 돈을 넣기 전에 서비스의 값을 한 번 보여주는 구간이다.

#### 구조

세 층으로 고정한다. 종목 수가 늘어도 제목과 검색창이 화면 밖으로 밀리지 않는다.

| 층          | 내용                                          | 동작                        |
| ----------- | --------------------------------------------- | --------------------------- |
| 상단 (고정) | `건너뛰기` · 제목 · 설명 · 섹션 헤더 · 검색창 | 스크롤 안 함                |
| 중단        | 종목 리스트                                   | 내부 스크롤, 하단 32px 패딩 |
| 하단 (고정) | CTA                                           | 항상 같은 자리              |

- 브랜드 마크를 넣지 않는다 — 직전 랜딩에서 이미 봤다 (§3 반복 금지)
- 하단 탭바 없음
- 우측 상단 `건너뛰기` — Secondary Text Action

#### 카피

> 관심 있는 종목을
> 골라주세요
>
> 고른 종목을 기준으로 매일 필요한 소식을 모아드려요.

#### 종목 리스트

1열 컴팩트 row. 2열 그리드는 6자 한글 종목명이 잘려 쓰지 않는다.

- 썸네일 36px · 종목명 16px/600 · `종목코드 · 시장` 13px
- 세로 패딩 11px, 행 사이 얇은 구분선
- **가격·등락률을 보여주지 않는다** — 고르는 화면이므로 종목 식별만
- 카드 배경·테두리 없음

#### 선택 인디케이터

우측 22px 원형 체크박스.

| 상태   | 배경   | 체크 | 링          |
| ------ | ------ | ---- | ----------- |
| 미선택 | 투명   | 없음 | `--border2` |
| 선택   | `--t1` | 흰색 | `--t1`      |

- 선택 시 종목명이 굵어진다
- 행 전체가 클릭 영역
- 카드 반전·색 채우기 같은 큰 상태 변화는 쓰지 않는다

#### 카운터와 CTA

- 섹션 헤더 우측에 `0개 선택` / `2개 선택`
- CTA는 **최소 1개**부터 활성 — 미선택 시 `관심 종목을 선택해주세요`(비활성), 선택 후 `FINCH 시작하기`
- 최소 개수를 강제하지 않는다. 하나만 담아도 브리핑이 켜지므로 문턱을 올릴 이유가 없다

#### 더 많은 종목 · 검색

- 리스트 하단 `더 많은 종목 보기` Text Action → 전체 종목으로 확장, 버튼이 `접기 ⌃`로 바뀐다
- 섹션 제목도 `국내 주요 종목` → `전체 종목`
- 검색창은 **확장 상태에서만** 나타난다. 기존 검색 로직(종목명·종목코드 부분 일치) 재사용
- 검색 중에는 `더 많은 종목 보기`를 숨긴다
- 결과 없으면 안내 한 줄
- 거래정지 종목은 확장 목록에만 나오고 `거래정지` 라벨이 붙는다. 담는 것 자체는 막지 않는다

#### 완료 후 홈

- **관심 종목 탭이 기본으로 열린다** — 고른 종목이 소식 한 줄과 함께 보인다
- AI 브리핑이 켜진다 — "관심 종목에서 오늘 확인할 소식이 N건 있어요."
- `관심 종목을 담으면 소식을 모아드려요` 빈 카드는 자동으로 사라진다
- 총자산 0원은 남기되, 입금 CTA를 검정 버튼이 아니라 회색 액션 로우로 낮춘다 — 입금이 첫 행동처럼 보이지 않게

#### 건너뛴 경우

홈 상단에 관심 종목 유도 카드를 노출한다. 온보딩으로 되돌리지 않는다.

#### 미확정

**"국내 주요 종목" 의 선정 기준.** 현재는 종목 목록 앞에서 순서대로 고른 것이다. 실제로는 시가총액 상위 같은 기준이 필요하지만 해당 API가 없다. 랭킹·추천 API는 만들지 않는다. 기준이 정해지기 전까지도 **서비스 종목(30개) 안에서만 고른다** — 밖의 종목은 고르면 관심 종목 등록이 막힌다(FINCH-300).

### 7.17 브리핑 전체 — 데일리 브리핑

홈 상단의 검정 AI 브리핑 카드를 누르면 오는 화면. **읽는 화면이고 체류가 짧다.**

구조:

1. `‹` 뒤로 + 화면 제목 `데일리 브리핑`
2. AI Glyph + `AI 데일리 브리핑` 라벨
3. 건수 제목 — `오늘 확인할 소식 N건`
4. 분류 요약 한 줄 — `정책 1 · 공시 1 · 실적 2`
5. `핵심 소식` — 한 건만. 좌측 세로선으로 강조
6. `오늘의 다른 소식 N건` — Flat List
7. 라벨 확장형 AI 버튼

소식 항목:

- 종목 썸네일 + 종목명 + (`확인 필요`) + 등락률
- 제목
- 한 줄 해석 — 그 소식이 내 종목에 무엇을 의미하는지
- 근거 캡션 — `유형 · 출처 · 날짜`

Rules:

- **탭바가 없는 화면이다.** AI 버튼을 라벨 확장형 플로팅으로 둔다 — `브리핑 물어보기`.
  §6 "적용 범위"가 정한 유일한 예외이고, 읽다가 생긴 질문을 그 자리에서 이어가기 위한 것이다
- **하단 여백을 버튼 높이보다 크게 둔다.** 스크롤 끝에서 마지막 소식이 버튼에 가리지 않아야 한다
- 근거는 뱃지가 아니라 **캡션 한 줄**이다 (§9 근거 표기)
- 등락률에만 등락색을 쓴다. 제목·해석·캡션은 중립색이다
- `확인 필요`만 약한 Attention. 유형 라벨은 Neutral (§7.11과 같은 규칙)
- 핵심 소식을 카드로 감싸지 않는다. 세로선과 여백으로 위계를 만든다
- 해석 문장은 단정하지 않는다 — `~일 수 있어요` / `~예요` (§13)

### 7.18 입금

모의 결제로 예수금을 채운다. 네 단계다 — 결제 준비 → 결제창 → 승인 → 확정.

**예수금이 늘어나는 시점은 마지막 확정 하나뿐이다.** 입금 화면에서 확인을 눌렀다고 성공으로 표시하지 않는다.

#### 입금 화면

한 화면 안에서 세 단계가 이어진다.

1. **금액 입력** — 직접 입력 + 프리셋 `+1만` `+10만` `+100만`. 입력값은 Display 크기
2. **한도 안내** — 1회 한도 · 누적 한도 · 잔여 한도 세 값. 화면이 계산하지 않고 서버 값을 그대로 쓴다
3. **결제 수단** — 카카오페이 · 계좌이체 둘뿐. 고른 값에 따라 다음 화면이 갈린다
4. **확인** — 결제 수단 · 입금 금액 · 입금 후 예수금. `입금은 취소할 수 없어요.`를 고정 노출한다

한도를 넘으면 원형 `!` + 문구다. 빨간 박스를 쓰지 않는다 (§10).

#### 모의 이체

결제 수단이 계좌이체일 때 도착한다. 은행 이체 승인을 흉내 내는 시연용 화면이다.

- 입금 금액과 결제 건 식별값 요약
- 시나리오 선택 — `성공`(기본) · `잔액 부족` · `한도 초과` · `시간 초과`
- **은행·계좌번호 입력 필드를 만들지 않는다.** 모의 서비스라 받아도 쓰는 곳이 없다

#### 결제 복귀

결제창에서 돌아오는 자리다. **바텀시트로 만들지 않는다** — 외부 브라우저 이동에서 돌아오므로 독립 화면이어야 한다.

- 성공: 확정 진행 중 → 확정 완료. 입금 금액과 입금 후 예수금을 보여준다. 주 동작 `매매 시작하기`, 보조 `홈으로`
- 실패: 원형 `!` + 사유 한 줄. 피드백을 붙이지 않는다
- **한도 초과·금액 불일치에는 `다시 시도`를 주지 않는다.** 그 결제 건은 되살릴 수 없어 `입금 화면으로`만 준다
- 그 밖의 실패에는 `다시 시도`를 준다. 결제 만료(15분)도 실패 상태로 처리하고 별도 화면을 만들지 않는다
- **어느 실패든 빠져나갈 보조 동작을 함께 둔다.** 이 화면에는 탭바도 뒤로가기도 없어 주 동작 하나만 두면 갇힌다
- 한도 초과 문구는 입금 화면과 **같은 문장**을 쓴다. 남은 한도 숫자가 들어간 쪽이다 — 같은 사유인데 문장이 갈리면 다른 문제로 읽힌다

### 7.19 출금

예수금을 뺀다. 진입점은 마이페이지, 입금과 같은 자리다.

- 출금 가능 금액은 예수금 전액이다. 별도 한도가 없다
- **금액 입력 하나가 유일한 입력이다.** 옆에 `전액`을 둔다
- 밑줄은 상태로 말한다 — 미입력 `--border2`, 입력 `--t1`, 초과 `--t3`
- CTA는 항상 `출금하기`다. 유효하지 않으면 비활성으로만 표현하고 버튼 문구를 바꾸지 않는다
- 초과 안내는 버튼이 아니라 입력 영역 옆 원형 `!` 줄에서 한다

**하지 않는 것**

- 출금 수단(은행·계좌번호) 입력을 만들지 않는다
- 금액 프리셋 버튼을 만들지 않는다. 입금에만 있는 것이다 (`전액`은 출금 가능 금액에 붙는 것이라 다르다)
- 별도 확인 단계를 만들지 않는다. 입금에만 있는 것이다

#### 입금 한도는 돌아오지 않는다

누적 입금액은 계좌 평생 기록이라 출금과 무관하다. 되돌리면 입금·출금을 반복해 한도를 무한히 우회할 수 있다.

화면 하단에 `i` + 캡션 두 줄로 알린다. 카드로 감싸지 않는다 — 안내가 금액 입력보다 먼저 보이면 안 된다.

> 출금해도 입금 한도가 다시 늘어나진 않아요.
> 이전에 입금한 금액도 한도에 포함돼요.

### 7.20 랜딩 · 로그인

앱을 처음 열면 오는 화면. **로그인 화면을 따로 두지 않는다** — 이 화면의 `카카오로 시작하기`가 그 역할을 겸한다.

구조:

1. 브랜드 마크
2. 롤링 카피
3. 한 줄 설명
4. `카카오로 시작하기`
5. 약관 동의 안내

카피:

> `펀드`에는 `매니저`, `세금`에는 `세무사`, `주식`에는 `FINCH`가 있다.
>
> 쏟아지는 공시와 뉴스에서 내 종목에 필요한 정보만 골라내고,
> 계좌 전체의 흐름까지 함께 정리합니다.

Rules:

- 앞의 세 짝(`펀드/매니저` · `세금/세무사` · `주식/FINCH`)은 세로로 롤링해 교체된다. 마지막에 `주식 · FINCH`로 멈춘다
- **브랜드 마크는 이 화면에만 크게 쓴다** (112~132px, §3). 제품 UI 안에서 반복하지 않는다 — 온보딩(§7.16)이 마크를 넣지 않는 이유다
- 하단 탭바 없음
- 카카오 버튼은 **카카오 가이드가 지정한 색·로고를 그대로 쓴다.** 우리 토큰으로 덮지 않는다. 유일한 예외다
- 약관 안내는 Caption. 링크만 `--t1`로 구분하고 밑줄을 쓰지 않는다
- 이 화면에서 AI 를 설명하지 않는다. 기능 나열도 하지 않는다

**카카오 콜백**(`/oauth/kakao`)은 화면 요소가 없다. 인가 코드를 토큰으로 바꾸는 사이의 자리이므로 로딩 표시만 두고 절을 따로 두지 않는다.

## 8. AI Component System

AI 기능은 공통 UI 문법을 사용한다.
**화면마다 새 AI Card를 만들지 않는다.**

AI 슬롯은 **6종**이다 — 브리핑 · 종목 분석 · 주문 전 점검 · 포트폴리오 진단 · 수익률 원인 · 채팅. 인스턴스 수와 슬롯 종류를 혼동하지 않는다. `requestId 하나 = 피드백 슬롯 하나` 규약은 슬롯 종류 기준이다.

### 8.1 `AISummary`

정상 AI 결과의 Compact Summary.

구조:

1. 공통 AI Glyph + 기능 Label
2. 핵심 결론 최대 2줄
3. 핵심 Meta 최대 2개
4. 필요 시 Chevron

Style:

- Dark Surface (`--ai-surface` #24272C)
- Radius **12px**, Padding **18px**
- White Main Copy
- Gray Secondary
- AI Accent는 핵심 결과에만
- Divider X
- Bullet List X
- Full-width Button X
- Card 전체 Clickable
- Radius / Padding / Header 위치 통일

적용:

- 홈 AI 브리핑
- 포트폴리오 AI 진단
- 종목 AI 분석 요약
- 수익률 분석 요약
- 주문 전 점검

### 8.2 `AIInline`

기존 금융 정보에 붙는 짧은 AI Insight / Entry.

구조:

- 공통 AI Glyph
- Title
- Secondary Copy
- Chevron

Style:

- 큰 Dark Background 없음
- 기본 Background 또는 Light Surface
- 짧고 가볍게

적용:

- 홈 `오늘 내 자산은 왜 올랐을까요?`
- 마이페이지 `나의 투자 기준`
- `나의 투자 기준` 상단 Intro
- 기타 짧은 AI 진입점

### 8.3 `AIDetail`

상세 AI 분석 화면.

구조:
`결론 → 근거 → 위험/확인할 점 → 내 계좌 영향 → 일정/기준 → 출처 → Feedback`

Rules:

- 기본 Background 위 Flat Section
- 모든 Section을 Card로 만들지 않는다
- 상세 분석 전체를 하나의 Dark Card에 넣지 않는다
- Section 간 충분한 여백

### 8.4 Common AI Header

- AI Glyph 위치 / 크기 통일
- 기능 Label 예:
  - `AI 브리핑`
  - `AI 진단`
  - `AI 종목 분석`
  - `AI 수익 분석`
  - `AI 주문 전 점검`
- Label은 Small / Secondary
- Main Copy보다 강하지 않게

## 9. AI Evidence & Feedback

### 근거 표기

**뱃지를 쓰지 않는다.** 응답 블록 최하단에 캡션 한 줄로 종류만 나열한다.

```
08.28 09:00 기준 · 공시 · 뉴스 · 자체계산
```

- 위치: 응답 블록 최하단, Caption 크기
- 뱃지 · 링크 아이콘(↗) · 점선 테두리 · 개별 출처 링크를 쓰지 않는다
- 종류를 나열만 하고 개별 출처로 링크하지 않는다
- `AIDetail`에서도 같다. 상세 화면이라고 뱃지를 되살리지 않는다

과거 안(뱃지 7종 · 외부는 링크 · 내부는 점선)은 폐기했다. 모든 응답 블록에 뱃지가 반복되면서 화면마다 장식이 쌓였고, "AI 표시는 상단에서 한 번만"으로 정리했다.

### Feedback Rule

**requestId 하나 = Feedback Slot 하나**

- Section마다 붙이지 않는다
- 응답 블록 최하단에 하나
- `도움됐어요 / 아쉬워요`
- Compact Neutral Secondary Button
- Green / Red 사용 금지

#### 동작

- **`도움됐어요`** — 누르면 바로 전송
- **`아쉬워요`** — 사유 바텀시트를 연다

사유 바텀시트:

- 사유 칩 **6종 복수 선택** — 숫자가 틀렸어요 · 관련이 없어요 · 오래된 정보예요 · 너무 뻔해요 · 이해하기 어려워요 · 근거가 이상해요
- 자유 입력 한 줄 (선택)
- 하나라도 고르거나 적으면 `의견 보내기` 버튼이 나타난다
- 전송 후 슬롯은 `보냈습니다`로 바뀐다
- 슬롯 3곳(종목 상세 AI 탭 · 채팅 · 수익률 분석)이 같은 시트를 쓴다

**실패 / 데이터 부족 자리에는 Feedback을 노출하지 않는다.** 재시도가 유일한 주 동작이다.

### 표현 규칙

- `긍정 요인 / 부정 요인` 표현 금지
- 대신:
  - `시장이 주목하는 요인`
  - `확인해볼 위험`
  - `공시·실적에서 확인된 위험 요인`
- AI가 매수·매도를 단정적으로 지시하지 않는다

X `이 종목은 사지 않는 것이 좋습니다.`
O `반도체 비중이 48%예요. 한 업종이 흔들리면 계좌 전체도 함께 움직일 수 있어요.`

## 10. States

### Loading

- Skeleton 우선
- AI 응답은 `확인하고 있어요` + 절제된 점 모션
- Loading 때문에 전체 화면 구조가 크게 흔들리지 않게

### Empty

`데이터가 없습니다`를 쓰지 않는다.

예:

> 아직 관심 종목이 없어요.
> 관심 있는 종목을 담아보세요.

### AI 실패

재시도 가능한 오류.

재시도 가능한 코드는 화이트리스트로 관리한다. 모르는 코드는 재시도 불가로 취급한다.

| 재시도 | 코드                                                                                   |
| ------ | -------------------------------------------------------------------------------------- |
| 가능   | `RETRIEVAL_FAILED` · `LLM_TIMEOUT` · `AI_UPSTREAM_UNAVAILABLE` · `AI_UPSTREAM_TIMEOUT` |
| 불가   | `INSUFFICIENT_DATA` · `GUARDRAIL_BLOCKED` · 그 밖의 모르는 코드 전부                   |

UI:

- Dark AI Card 사용 금지 — 흰 면을 쓴다
- 기본 Background 위 Status UI
- Red Warning Box 금지

카피:

> 분석을 불러오지 못했어요.
> 잠시 후 다시 시도해 주세요.
> **[다시 시도]**

- Retry가 주 동작
- Feedback 노출 금지
- 채팅의 실패 상태도 같다. 검정 말풍선 안에 넣지 않는다

### AI 데이터 부족

오류가 아니라 아직 조건이 충족되지 않은 상태.

- Dark AI Card 사용 금지
- Retry 없음
- 해당 슬롯의 **실제 활성 조건**을 알려준다
- 모든 슬롯에 동일한 숫자 조건을 하드코딩하지 않는다

예:

> 아직 분석할 정보가 충분하지 않아요.
> 필요한 기록이 조금 더 쌓이면 분석 결과를 볼 수 있어요.

슬롯별 예:

- 수익률 원인 → 해당 기능의 실제 매매내역 조건
- 포트폴리오 진단 → 실제 보유 종목/업종 조건
- 종목 분석 → 필요한 공시/시세 데이터 조건

### AI 가드레일 차단

**데이터 부족과 다른 상태다.** 정보가 없어서 못 답하는 게 아니라 **답하면 안 되는 질문이라 막은 것**이다.
`GUARDRAIL_BLOCKED`(422)에 해당하고, 명세는 이 코드를 "재시도 유도 금지"로 구분한다.

주로 AI 채팅에서 나온다 — 매수·매도 판단이나 금액을 정해 달라는 요구.

- **위의 데이터 부족 문구를 쓰지 않는다.** `필요한 기록이 조금 더 쌓이면 볼 수 있어요`는
  거짓이 된다. 기록을 쌓고 다시 물어도 영원히 열리지 않는다
- **조건부 표현을 쓰지 않는다.** `~하면 볼 수 있어요` 형태는 기다리면 열린다는 인상을 준다
- **Retry 없음.** 다시 눌러도 같은 답이 온다
- **Feedback 없음** (§9 Feedback Rule)
- 채팅 말풍선 안에서 처리한다. 검정 AI 카드로 만들지 않는다
- 못 하는 것과 **대신 하는 것**을 한 번에 말한다. Finch 는 판단을 대신하지 않고 근거를
  정리하는 제품이다 (§2 원칙 4)
- 사용자를 나무라지 않는다. 질문이 잘못됐다는 뉘앙스를 만들지 않는다

카피:

> 오를지 내릴지는 제가 답할 수 없어요.
> FINCH는 사거나 팔라고 말하지 않아요. 대신 판단에 필요한 재료를 정리해드려요.

### 관심 종목 한도

관심 종목이 한도에 찼는데 더 담으려 할 때 서버가 거절한다.

- **토스트 하나로 끝낸다.** 별도 화면이나 모달을 만들지 않는다
- 문구에 한도 숫자와 사용자가 할 일을 함께 넣는다
- 담기 버튼을 영구 비활성으로 만들지 않는다. 하나 빼면 다시 담을 수 있다
- 이미 담긴 종목을 빼는 것은 한도와 무관하다. 막지 않는다

> 관심 종목은 50개까지 담을 수 있어요. 홈의 관심 종목에서 하나 빼고 담아주세요.

### 주문 — 서버가 거절

화면이 `최대 N주`로 미리 막아도 시장가라 실제 체결 금액이 다를 수 있다. 시세가 움직이면 미리 막았는데도 서버가 거절한다.

- **주문 화면에 머문 채로 알린다.** 결과 화면으로 넘기지 않는다. 입력한 수량이 남아 있어야 고칠 수 있다
- 체결가 · 수량 · 필요한 금액 · 가진 금액 · 모자란 금액을 보여준다
- **화면에 보이는 수량 × 체결가 = 필요한 금액이 성립해야 한다.** 숫자가 서로 안 맞으면 리뷰어가 반올림 버그로 읽는다
- 할 수 있는 일 두 가지를 준다 — `수량 줄이기` · `입금하기`. `수량 줄이기`는 실제로 수량을 낮춰야 한다
- 원형 `!` + 문구. 빨간 박스를 쓰지 않고, 매수 색(`--up`)으로 에러를 칠하지 않는다

### 미기록 상태

경고가 아니다.

- 작은 Dot + 문장
- Warning Triangle / `!` / 큰 Red Badge / 빨간 배경 금지
- Dot은 Accent 또는 Notify
- 텍스트는 Secondary
- 기록 완료 즉시 제거
- `✓ 완료`를 계속 표시하지 않는다

## 13. Copy & Microcopy

### 용어

**화면 문구와 계약 문서의 용어가 갈린다. 사고가 아니라 결정이다.**

| 뜻                     | 화면 문구 (이 문서 · 프로토타입 · 프론트 구현) | 계약 · 명세 · 필드명                   |
| ---------------------- | ---------------------------------------------- | -------------------------------------- |
| 예수금을 채우는 것     | **입금**                                       | 충전 · `/deposits` · `depositedAmount` |
| 하단 4번째 탭          | **마이페이지**                                 | —                                      |
| Finch가 물어다 놓는 것 | **알림함**                                     | —                                      |

- **바뀐 것은 사용자에게 보이는 말뿐이고 계약은 그대로다.** `apiSpec` 4장 제목과
  `contracts.md` C47 · C49 는 "충전" 을 쓰고, 코드 주석이 그 절을 인용한다. 용어를 맞추면
  근거 추적이 끊긴다
- 필드명·경로는 애초에 영어(`/deposits` · `depositedAmount` · `depositId`)라 화면 용어와
  무관하다. 바꿔서 얻을 것이 없다
- `featureSpec` · `ia.md` 도 "충전" 을 유지한다. 두 문서는 백엔드·AI 도 참조한다
- **이 문서에서 계약 용어를 인용할 때는 원문 그대로 쓴다.** 인용인지 화면 문구인지 헷갈리면
  절 번호를 함께 적는다

`알림함`은 우편함 → 메일 → 알림함으로 두 번 뒤집힌 이름이다. 되돌리지 않는다.

### Tone

Finch는 다음처럼 말한다.

- 짧고 구체적
- `~해요 / ~했어요`
- 자연스러운 한국어
- 차분하지만 딱딱하지 않음
- 과하게 귀엽거나 감정적이지 않음
- 시스템/개발 용어를 사용자에게 노출하지 않음

### 피하는 표현

- 성공적으로
- 정상적으로
- 처리되었습니다
- 완료되었습니다
- 오류가 발생했습니다
- 데이터가 없습니다
- 해당
- 확인 바랍니다
- 유효하지 않습니다
- 진행하시겠습니까?

### Toast

결과가 중요하면 구체적인 숫자를 넣는다.

X `입금됐어요.`
O `1,000,000원을 입금했어요.`

X `관심종목에 추가되었습니다.`
O `관심 종목에 담았어요.`

X `삭제되었습니다.`
O `검색 기록에서 지웠어요.`

X `요청에 실패했습니다.`
O `잠시 문제가 생겼어요. 다시 시도해 주세요.`

### Confirmation

X `정말 삭제하시겠습니까?`

O

> 이 투자 기준을 삭제할까요?
> 삭제하면 Finch가 이후 분석에서 이 기준을 참고하지 않아요.

### Empty State

X `데이터가 없습니다.`

O

> 아직 최근에 본 종목이 없어요.
> 종목을 둘러보면 여기에 모아둘게요.

### AI Copy

보고서체를 피한다.

X `반도체 업종 집중도가 높은 상태입니다.`

## 14. Do / Don't

### Do

- 중요한 숫자는 크게
- White / Graphite 중심
- AI 정상 결과는 Dark Summary로 명확히 구분
- AI 설명은 짧고 구조적으로
- 위험 요인을 근거와 함께 제공
- 보유 종목 / 관심 종목 / 투자 기록을 개인화 중심으로 사용
- 기록이 필요한 일은 알림함에 쌓아 두고 재촉하지 않기
- 같은 역할의 컴포넌트는 공통 UI로 재사용
- Section 내부는 Compact, Section 사이에는 충분한 여백

### Don't

- 제품 UI에서 상세 캐릭터 일러스트 반복
- 화면 전체 베이지 / 웜톤
- 흰 배경에서 AI Accent 남발
- 종목 로고에 진한 채도색 남발
- 모든 정보를 큰 카드로 감싸기
- 모든 버튼을 Pill로 만들기
- 전체 화면 Glassmorphism
- 과도한 Gradient / Shadow
- 상승·하락 색을 장식용·상태용으로 사용
- AI가 매수·매도를 단정적으로 지시
- 체결 직후 강제 모달로 기록 요구
- 매도 체결 후 매도 이유 기록 기능 임의 추가
- 모든 숫자를 한 화면에 노출
- AI Card마다 다른 아이콘 / Padding / Radius 사용
- 실패/데이터 부족을 정상 Dark AI Card 안에 표시
- 근거 뱃지 되살리기
- 검정 Surface 위에 `--t2` 같은 진한 회색 텍스트 사용

## 15. Final Direction

### Core Formula

> **White / Graphite = 신뢰감과 금융 정보**
> **Dark Surface = AI 정상 결과**
> **AI Glyph = AI가 관여한 순간의 공통 Signifier**
> **AI Accent = 검정 위 핵심 하나**

### Brand Formula

> **Finch는 귀여움을 전면에 내세우는 마스코트 앱이 아니라, 차분한 투자 UI 안에서 AI가 관여하는 순간을 명확하게 보여주는 서비스다.**

- 금융 데이터 화면에서는 브랜드 일러스트를 반복하지 않는다
- 제품 UI의 AI 표현은 공통 AI Glyph와 Component로 통일
- 한 화면에서 AI를 과도하게 반복하지 않는다

### Visual Direction

- **Base:** White & Graphite
- **AI Summary:** `--ai-surface` #24272C + White
- **AI Accent:** `#E9C77F`, Dark Surface 한정
- **Notification:** `--notify` #D94A4A Small Dot
- **Type:** Pretendard + tabular-nums
- **Shape:** 카드 **12px** Radius
- **Structure:** Card 남발보다 Typography / Spacing / Alignment
- **Effects:** Shadow 최소화
- **Interaction:** 필요한 순간에만 Motion

### Product Goal

**목표는 "귀여운 투자 앱"이 아니다.**

> **신뢰할 수 있고, 정보가 많아도 빠르게 읽히며,
> AI를 만나는 순간이 일관되고 분명한 투자 앱.**
