## 화면 경계 — 시트는 화면이 아니라 화면들이 공유하는 층이다

`is404` 뒤 공통 블록(L2855–L3025)에는 FAB(L2855–L2859) · 탭바(L2861–L2889) · **시트 템플릿 6개**(L2891–L3021) · 토스트(L3023–L3025)가 있다. FAB 는 브리핑 문서 D 절, 탭바는 2차 탭바 문서와 종목 상세 문서 E 절이 셌다. 여기는 **시트 6개와 토스트**다.

**"바텀시트 8종" 이 아니라 템플릿 6개 · 상태값 7개다.** 2차 탭바 문서 L22 가 "바텀시트 8종(L2891–L3032)" 이라고 적었는데 그 범위를 실측하면 `<div class="sheet">` 는 여섯이고(`sheetTerm` · `sheetTerms` · `sheetDelFact` · `sheetFbReason` · `sheetRecord` · `sheetInsight`), `sheet` 상태값은 `terms`·`privacy` 가 템플릿 하나를 공유해 일곱이다(app-logic.js:384, 880-882, 1024 → L3417, L3913–L3915, L4057). `ia.md` §1 "바텀시트" 절(L260-273)은 "상태값 6개, 템플릿 5개" 라고 적었는데 그것은 `sheetFbReason`(이슈 #32 회신 뒤 추가) 이 빠진 낡은 수다. 8 이 어디서 나온 수인지는 확인하지 못했다 — 토스트와 FAB 를 더한 것으로 보이지만 **불확실**하다.

## 상태 분기를 어떻게 셌나

시트 블록 안의 `sc-if` 는 열이다(시트 여닫는 7 + 시트 안 4 + 토스트 1 = 12, 여닫음 중 `sheetTerms` 는 상태값 둘이 하나).

| 시트   | 조건 태그                                                           | 갈래                                  |
| ------ | ------------------------------------------------------------------- | ------------------------------------- |
| 사유   | `fbCanSend` (L2955)                                                 | `의견 보내기` 버튼 노출               |
| 기록   | `o.on` (L2974) · `recordCanSave` (L2982) · `recordCantSave` (L2985) | 라디오 선택 / 저장 활성 / 저장 비활성 |
| 토스트 | `toast` (L3023)                                                     | 표시                                  |

**시트 안의 로딩·실패는 프로토타입에 없다.** 저장·삭제·전송이 전부 즉시 상태 전환이다. 우리 구현은 기록 시트·삭제 시트에 `isPending`·`isError` 가 있다 — 그 차이도 표에 넣었다.

## 프로토타입 ↔ `design.md` 어긋남

**고치지 않았다.** 두 근거가 서로 다른 말을 하는 자리만 모았다.

1. **삭제 확인 문장** — design.md L1436-1437 `이 투자 기준을 삭제할까요? / 삭제하면 Finch가 이후 분석에서 이 기준을 참고하지 않아요.`, 프로토타입 L2932–L2933 `… / 삭제하면 FINCH가 이후 분석이나 답변에서<br>이 기준을 참고하지 않아요.`. `FINCH`/`Finch` 와 `분석에서`/`분석이나 답변에서` 두 곳이 다르다. 우리 구현은 셋째 문장(`이 기록을 삭제할까요? …`)이다
2. **삭제 버튼의 빨강** — 프로토타입 `.btn.rd{background:var(--up)}`(L1098) 은 **상승색**을 삭제 버튼 면에 쓴다. design.md L181 "상승·하락 색상은 금융 의미 전달에만, 상태용으로 쓰지 않는다" 와 부딪히고, L702 "Confirmation 단계에서만 Red" 와는 맞는다 — design.md 안에서도 두 줄이 긴장한다. 우리는 검정(primary)이다
3. **기록 시트의 직접 입력 노출** — design.md L594 "`직접 입력` 선택 시에만 Text Field 펼침", 프로토타입 L2979 는 textarea 가 **항상** 보이고 선택지 4개는 라디오다(입력하면 라디오가 풀린다). 우리는 선택지가 없어 비교가 성립하지 않지만, 되살릴 때 어느 쪽인지 정해야 한다
4. **기록 시트 저장 버튼 라벨** — design.md L595 `매수 이유 저장하기` 와 프로토타입 신규 모드 L3984 가 같고 수정 모드는 `수정 저장하기` 다. design.md 는 수정 모드를 적지 않았다. 우리는 `저장` 하나
5. **`—배`** — 용어 시트의 `termValue` 가 PER 없는 종목에서 `—배` 로 나온다(app-logic.js:945). design.md L456 이 금한 표기다. 종목 상세 문서 "어긋남" 4번과 같은 계열
6. **시트 개수** — `ia.md` L262 "상태값 6개, 템플릿 5개" ↔ 실측 상태값 7·템플릿 6(`fbreason` 추가). 2차 탭바 문서 L22 "8종" 도 실측과 다르다. design.md 는 시트를 세지 않는다
