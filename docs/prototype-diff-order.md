프로토타입은 `side`·`qty`·`orderErr` 를 화면 상태로 갖고(app-logic.js:101, 128 → L3134, L3161) 종목 상세의 `toBuy`/`toSell` 이 `side` 를 정한 뒤 `order` 화면으로 넘긴다. 우리는 `?side=` 쿼리로 받는다(`ia.md` §2).

표에 이미 넣은 것 말고, 따로 확인해 어긋나지 않은 것들이다.

- 라우트 `/stocks/:stockCode/order?side=buy|sell` 이 `ia.md` §1·§2 와 `routes.ts:49,99`·`orderSide.ts:13-16` 에서 같다
- 네비 제목 `매수`/`매도` 와 18px/700
- `수량` 섹션 제목·`maxNote` 문구·아래 14px·위 32px
- 수량 글자 28px/700, 밑줄 2px·아래 12px, `주` 18px
- −/＋ 버튼 40×40·radius 12·`aria-label` 문구
- 비율 세그먼트 넷과 `floor` 계산, 선택 상태 없음
- 요약 `.soft` 컨테이너와 `주문 후 예수금` 줄
- AI 점검 라벨 `AI 주문 전 점검`, `확인해볼 점` 머리 구조(점 + 라벨), 논지 블록의 왼쪽 선 + 날짜 + 원문 구조, `참고용 정보예요.` 문구

## 프로토타입 ↔ `design.md` 어긋남

**고치지 않았다.** 두 근거가 서로 다른 말을 하는 자리만 모았다.

1. **점검 슬롯과 제출 버튼의 거리** — design.md L530 은 "제출 버튼 바로 위", `ia.md` L544 는 "제출 버튼과 붙여 놓지 않는다. 오탭하면 주문이 나간다" 다. 프로토타입은 요약 바로 아래(L2013)라 제출 버튼과 멀다. 우리는 맨 아래 두되 여백 1.5rem 을 더했다(`OrderPage.tsx:187-191`)
2. **전후 비교의 예수금 줄** — design.md L535 는 "주문 전후 예수금" 을 구성 2번으로 적었고 프로토타입도 `예수금 124만 → 78만` 을 그린다(app-logic.js:750-753). 그런데 계약 응답 `before`/`after` 는 비율 지표 12개라 예수금 **금액** 전후가 없다(`shared/types/ai/orderPreview.ts:62-71`). 시안 둘 ↔ 계약이 갈린 자리다
3. **변화 없음 표기** — design.md L543 은 `17% · 큰 변화 없음`, 프로토타입은 `32% → 큰 변화 없음`(화살표 뒤, app-logic.js:755). 우리는 design.md 쪽이다
4. **거래정지 문구** — design.md L556 은 거래정지를 "탭바 캡슐이 `거래정지` 한 줄로 바뀐다" 로 종목 상세에 넘기고 주문 화면에는 두지 않았다. 프로토타입 `BLOCK` 도 장외·시세 2종만이다(app-logic.js:236-237). 우리 `orderBlockReason.ts:32` 는 `거래정지 종목이라 주문할 수 없어요.` 를 두어 **넷째 문장**이 생겼다(캡슐 세 갈래는 이슈 #54). 서버가 `STOCK_SUSPENDED` 를 `reason` 으로 내릴 수 있어 자리는 필요하지만 문구가 어디에도 없다
5. **`예상 주문 금액`** — design.md L517 과 프로토타입(L1993)은 `주문 금액`, 우리만 `예상` 을 붙였다. 사유는 주석에 있다(`OrderSummaryBox.tsx:7-10`)
6. **상한 초과 안내의 빨간 글씨** — design.md §7.7 L546, L558 과 §10 L1298 은 이 화면에서 빨간 경고를 쓰지 말라고 세 번 적었다. 프로토타입은 상한을 잘라 안내 자체가 없다. 우리 `text-danger` 안내(`OrderPage.tsx:225`)와 서버 거절 카드의 `bg-danger-surface`(`OrderPage.tsx:246`)는 두 근거 어디에도 없는 색이다 — 어긋남이라기보다 우리만 벗어난 자리라 여기 적어 둔다
