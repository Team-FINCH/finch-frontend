**플로팅 AI 버튼(`.fab`)은 브리핑에만 뜬다**(`showFab: ["briefing"]`, app-logic.js:377 → L3410). 2차 탭바 문서가 "브리핑 화면에서 다룰 자리" 로 남겨 둔 것이라 여기 D 절에서 센다. `.fab` 와 `.tabai` 가 공유하는 버튼 몸체(58px 원형·`--t1`·펼침 모션)는 2차 탭바 문서 C 절이 이미 셌으므로 `.fab` 에서만 다른 것만 적는다.

브리핑 응답은 `GET /ai/briefing` 하나고 홈 카드(2차 홈 문서 B 절)와 같은 쿼리(`useHomeBriefing`)를 쓴다. 이 화면은 그 `items[]`(최대 4건) 전체를 그린다.

## 상태 분기를 어떻게 셌나

`isBriefing` 안의 `sc-if` 는 셋이다. 프로토타입은 목 데이터라 **로딩·실패·빈 상태가 하나도 없다** — `briefKeys` 가 보유·관심 종목에서 항상 채워진다(app-logic.js:271 → L3304).

| 묶음      | 조건 태그                                         | 갈래                                  |
| --------- | ------------------------------------------------- | ------------------------------------- |
| 핵심 소식 | `briefTop` (L2808) · `briefTop.needCheck` (L2814) | 1위 항목 강조 블록 / `확인 필요` 라벨 |

우리 구현은 로딩·실패·빈 상태 셋이 더 있다 — 그 차이도 표에 넣었다.

## 프로토타입 ↔ `design.md` 어긋남

**고치지 않았다.** 두 근거가 서로 다른 말을 하는 자리만 모았다. `ia.md`·계약이 셋째 갈래를 만드는 곳은 그것도 적었다.

1. **AI 글리프 크기** — design.md §3 L108 은 "AI Inline / Header: 28~36px", 프로토타입 브리핑 머리 글리프는 22px(L2799)이고 AI 카드 헤더 글리프는 17px(L1889)다. 프로토타입 어디에도 28px 이상 글리프가 없다. `AiCard.tsx:26-27` 주석이 이미 "문서와 다름" 으로 적어 둔 것과 같은 계열
2. **항목 머리줄의 재료** — design.md L917 과 프로토타입(L2811–L2816)은 종목 썸네일·종목명·등락률을 요구하는데, 계약 응답(`AiBriefingItemSchema`, `briefing.ts:53-64`)에는 종목 코드 배열·카테고리·제목·본문만 있고 종목명·등락률·"확인 필요" 가 없다. 시안 둘 ↔ 계약이 갈린 자리다
3. **근거 캡션** — design.md L920 `유형 · 출처 · 날짜` 와 프로토타입 `meta`(L2819)가 같은 것을 말하지만, `citations` 는 현재 항상 빈 배열(C56)이라 "출처" 를 채울 재료가 없다. 유형(`category`)·날짜(`content.date`)만 있다
4. **본문 숫자의 등락색** — design.md L928 은 "등락률에만 등락색, 제목·해석·캡션은 중립색" 이고 프로토타입도 그렇다. `ia.md` L504 는 `segments[].direction` 이 있으면 적색·청색으로 칠하라고 적었다. 우리 `AiSegmentText` 는 `ia.md` 쪽이라 본문 안 숫자가 등락색이다
5. **빈 상태 문구** — 이것은 프로토타입과 design.md 가 갈린 것이 아니라 **우리 구현 안에서 갈린다**. 홈 카드 `아직 모을 소식이 없어요`(proto L1382, `BriefingSection.tsx`) ↔ 이 화면 `오늘은 모을 소식이 없어요.`(`BriefingFullList.tsx:56`). 같은 `status: 'empty'` 를 두 문장으로 부른다
