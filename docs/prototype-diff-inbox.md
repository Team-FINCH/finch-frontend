# 프로토타입 ↔ 구현 대조 — 알림함 (`/inbox` ↔ `isMail`)

- 작성: 2026-09-09 / 기준 커밋 **master `2febe11`**
- **1차 `prototype-diff.md`·2차와 같은 형식이다.** 표 칸 · 근거 표기 · 화면 경계 기준 · 상태 분기를 세는 법이 모두 같다. 새 형식을 만들지 않았다
- **판정 규칙은 [`prototype-diff.md` 의 "판정 규칙" 절](./prototype-diff.md)에 있다.** 여기서 다시 적지 않는다
- **`판정` 칸은 비어 있다. 사용자가 채운다.** `(잠정) 의견` 은 워커의 한 줄 소견이고 결정이 아니다
- `proto L####` 는 디코드본 기준 줄 번호다(4,164줄). `app-logic.js` 의 줄 번호 `N` 은 디코드본 `L(N+3033)` 이다

## 상태 분기를 어떻게 셌나

`isMail` 안의 `sc-if` 는 셋이고, 그 밖에 진입·퇴장 모션 클래스 `mailCls` 가 있다.

| 묶음 | 조건 태그                               | 갈래                       |
| ---- | --------------------------------------- | -------------------------- |
| 목록 | `mailEmpty` (L1535) · `mailHas` (L1542) | 빈 상태 / 목록             |

**로딩·실패는 프로토타입에 없다.** 우리 구현은 둘이 더 있다 — 그 차이도 표에 넣었다.

## 프로토타입 ↔ `design.md` 어긋남

**고치지 않았다.** 두 근거가 서로 다른 말을 하는 자리만 모았다. `ia.md` 가 셋째 갈래를 만드는 곳은 그것도 적었다.

1. **유형 태그의 색** — design.md L672-674 는 "유형 Label은 Neutral, `기록 / 확인 / 소식`마다 강한 색을 주지 않는다" 다. 프로토타입 `.tag.d`·`.tag.a`·`.tag.n` 은 청·주황·회 세 색이다(L1113–L1114, app-logic.js:118-120). 우리는 design.md 쪽(중립 하나)
2. **`확인 필요` 를 어떻게 약하게 강조하나** — design.md L673 은 "`확인 필요`만 약한 Attention" 이라고만 적었다. 프로토타입은 태그 `확인` 에 주황(`#B4790E`)을 줘서 그 역할을 하고 별도 `확인 필요` 글자는 없다. 우리는 태그를 중립으로 두고 `확인 필요` 글자를 굵게 더 붙였다(`InboxItemRow.tsx:51-55`). 위키 탭의 `확인 필요` 강조색 `#8A6B3D`(2차 포트폴리오 문서)와도 다르다 — "약한 Attention" 의 실체가 화면마다 다르다
